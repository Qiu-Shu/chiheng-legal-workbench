# 工作流与输入输出契约

## 最小输入

最低确认四项：目标文书、模式、我方角色/立场、预定用途。按需补充程序类别和阶段、受理机构及地域、关键日期、请求和最低目标、附件完整性、证据清单、既有承认和禁止披露事项。

缺少决定性信息时，只问当前阻断工作的一个问题。可以继续的部分继续，不用统一免责声明停止全部任务。

## 阶段 0：材料和风险底图

1. 记录目标文书的名称、版本、页数、已读范围及附件状态。
2. 区分我方、对方、第三人、法院或仲裁机构的陈述。
3. 建立事实登记和证据定位，不把“主张”写成“已证明”。
4. 确认程序、地域连接点、关键日期及法律研究截止日。
5. 用一页以内记录：己方目标、对方最强论点、己方最不利材料、适用法核验状态、决定性缺口。

若只有诉状而没有证据目录和证据正文，可以审查诉状内部逻辑，但不得得出“对方没有证据”。若文件乱码、扫描模糊或缺页，应定位具体缺口，不猜金额、日期、否定词或印章内容。

## 第一遍：候选攻击

每项候选攻击使用独立 ID，并记录：

- 被攻击命题及其在原文中的位置；
- 对请求、抗辩或程序后果的影响；
- 事实 ID、证据编号、文件和页码；
- 法律问题、当前来源和核验状态；
- 是原文已有主张、内部假说还是预测回应。

模式 A 不改善或改写对方原文后再攻击。模式 B 应把最强合法反方意见钢人化，但不得增加与案卷不相容的事实。

## 第二遍：逐项过滤

对每个候选项逐一运行全部失败模式及下列问题：

1. 它针对的请求或法律效果是否明确？
2. 适用于本程序、本阶段和本机构吗？
3. 举证责任和证明程度是否有依据？
4. 事实状态、自认范围和相反材料是否处理？
5. 规范版本、过渡条款、地域和时间是否匹配？
6. 引文是否在上下文中支持命题，是否遗漏条件和例外？
7. 是否查找并展示重大不利依据？
8. 对方最强短回应是什么，它是否消除该点的实质价值？
9. 提出该点会不会损害律师可信度？
10. 进入对外稿会不会产生新自认、权利处分或内部信息泄露？

给出 `保留 / 限定保留 / 待补证 / 待核法 / 删除 / 需律师决策`。理由应让复核人能根据材料检查，不要求展示模型私有思维链。

## 第三遍：重建

从零组织通过过滤的观点。先写决定请求或程序结果的承重意见，再写必要的回应和限制。默认不超过五个主要观点；第六项以后只有在争点独立且可能决定结果时保留，并说明原因。没有观点或只有一个观点均是合法结果。

不得把“未列为攻击点”“暂不讨论”“即便”自动变成对外承认。不得把内部预测、未核验网页、检索日志或删除理由混入拟对外稿。

## 输出层次

### 内部审查

必须显示审查对象、模式、程序、资料截止日、已读范围、风险底图、攻击取舍表、重大不利依据、事实争议状态、自认审批队列、缺口及来源限制。

### 拟对外稿

仅在目标、角色、材料范围和决定性依据达到可用条件时生成，并与内部审查分离。表头保留：

```text
文件性质：拟提交文本，待承办律师复核
审查对象与版本：按实际填写
材料截止日期：按实际填写
适用法核验日期：按实际填写
尚未核验的决定性事项：存在时列明
```

用户只要内部意见时，不生成拟对外稿。

## 缺口表达

每个缺口写成：`缺什么 → 为什么重要 → 已查范围 → 受影响结论 → 恢复条件 → 当前可交付的有限结果`。

待核法项还须给出可执行的下一步：`实际可用工具或官方入口 → 规范名称或去标识查询词 → 具体条款、上下文、版本及修改废止的核对动作`。只写“补法源”“核版本”或列一个首页不够；不知道名称、条号或深链接时不猜，改给主题查询词和筛选条件。未实际执行的路径明确标为“拟检索”，不得写成已检索或已核验。

停止的是受缺口影响的结论或对外用途，不是不加区分地停止全部任务。
