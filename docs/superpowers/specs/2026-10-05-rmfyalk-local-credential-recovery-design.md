# 人民法院案例库本机凭证更新后自动恢复设计

日期：2026年10月5日。用户已确认本设计，并补充要求：需要重新登录时提示用户，登录更新后验证网站实际可用。开始实施；设计确认不等于自动恢复已经通过验收。

后续状态：本轮工程实现、独立规格/质量复核及50专项/459全量/9合成STDIO验证已通过。2026-10-05用户正常重开后，当前正式工具已加载新版，主代理一次真实官网认证、单条检索及对应正文三步全部通过。现场验收不等于永久授权或真实换证免重启试验完成；后者仅有工程验证。下文第1节为设计时的旧代码基线，不是当前状态。操作见 `docs/rmfyalk-credential-recovery-guide.md`，证据见 `verification/rmfyalk-recovery-2026-10-05/`。

本次只改造现有人民法院案例库连接，让各律师 Skill 继续共用它。自动恢复指用户在原本机文件保存新凭证后，下一次工具调用自动读取和使用新值，不要求反复重启。它不是长期凭证、自动登录或网站授权续期。

## 1 当前接入事实

现有 `menglu-rmfyalk` 使用既有 STDIO 包装器，加载 Treasury 中的开源 MCP。`client.py` 在启动时加载 `.env`，随后将凭证保存在进程和 HTTP 客户端请求头中。因此更新文件不保证已运行进程立即更新。

2026年10月5日正式工具返回认证过期，本地到期辅助检查也显示到期。10月4日临时会话成功是历史记录，不证明今日认证有效。详项目外层 `outputs/人民法院案例库本机接入验收-2026-10-04.md`。

凭证文件位于 Treasury 的 `sources/legal-tools/人民法院案例库MCP/.env`，不是 `config/.env`。本设计不读取或改写其实际值，不要求用户把凭证发到聊天。

## 2 方案选择与范围

采用“工具调用前读取本机文件”的轻量方案：复用现有进程、依赖和工具，不增加常驻监视器、HTTP 服务、定时任务或自动浏览器操作。正常使用时无须为每份新凭证重启；首次部署新代码仍需重建一次连接。

仅手动重启无法避免今后再次使用旧值；另建文件监视服务会增加运行和迁移负担。本轮均不采用。后台系统通知、定时提前提醒、浏览器 Cookie 自动同步、自动登录、验证码代办、官方 API 申请、案例入库与移植包重建不在本轮范围。

“提示”是本次工具调用返回明确中文原因及恢复步骤，不是电脑无人使用时主动弹窗。“恢复”只在用户再次查询或检查连接时发生，不自动重放已失败的查询，也不把未取得的数据补写为成功。

## 3 用户操作与安全边界

1. 用户正常使用案例检索；认证失败时看到“未设置、已过期、官网拒绝、文件不可读或网络失败”等准确状态。
2. 用户本人在 [人民法院案例库官网](https://rmfyalk.court.gov.cn/) 完成登录及网站要求的验证，仅在原本机文件更新 `RMFYALK_TOKEN` 并保存。
3. 下一次检查或查询自动加载新文件内容；使用既有认证检查工具依次完成官网认证、检索一条案例、读取该命中的详情，三步均成功且凭证未在期间变化，才报告“网站实际可用”。只读到文件、只完成认证或只得到空检索结果，均不算完整可用验证。

重新登录提示必须明确写“需要您重新登录官网”，附官网链接和本机更新步骤，不让用户猜测是否需要登录。网络、证书、接口异常不冒充登录失效；三步验证中途失败时逐项说明已通过和未通过的步骤。认证检查只做一次首条命中的只读检索及详情，不额外批量采集、不导出或入库。

恢复提示不得引导聊天粘贴凭证。凭证、Cookie、JWT 负载、账户 ID、手机号、带登录回调参数的 URL 不得进入工具结果、日志、验收报告、Obsidian 或源码/数据迁移包。记录状态及检查时间即可，不记录凭证摘要。

本轮不改用户的真实凭证文件，不自动保存或修正用户输入。权限不合要求时给出原因和本机处理说明，不悄悄改权。用户在其他 Mac 上仍须单独登录授权，不能把认证复制当作可移植法库。

## 4 文件读取与认证状态

本机文件是此流程唯一持续认证来源，不让启动时遗留的 `RMFYALK_TOKEN` 环境值覆盖后来保存的文件。保留 `.env` 其他配置用途；只为本流程显式读取目标键，不执行文件内容，不做环境变量插值。

凭证路径相对既有 MCP 源码定位，不增加用户名或机器绝对路径常量。仅允许预定的普通文件、当前用户所有、仅所有者可访问；拒绝符号链接。缺失、空值、不可读、格式错误、重复目标键、过大文件和宽松权限分别返回无秘密的中文状态，停止在线认证请求，不继续使用缓存的旧值。读取上限为64 KiB；不读取其他目录寻找替代凭证。

每次工具调用和每次实际 HTTP 请求前检查文件内容；不能只用修改时间或文件长度判断变化。文件保存期间暂时缺失/写到一半时安全停止；下一次调用仍可重新读取。正常工具不得写文件或把内容放入进程全局环境。

本地只按可解析的数字 `exp` 辅助发现已到期凭证；不解码或展示其他身份字段，不假定固定四小时有效期。不含可用到期字段的非空凭证仍需官网验证，不能标成有效。本地解析不构成签名验证。

在内存中按实际 `RMFYALK_TOKEN` 值区分凭证代次。同一份凭证被本地判定到期或官网以 HTTP 401、业务响应 `code=401` 拒绝后，不继续用它反复访问官网。实际凭证值改变才解除这一代的认证阻断；新值仍须通过真实请求验证。仅改注释、引号、文件时间或重复保存同一值，不当作续期。已发出的并发请求可完成，但已知该代失效后的新请求不得再发出。

网络、超时、TLS 错误和非认证业务错误不得误报“过期”，也不得清空或覆盖凭证。只返回安全类别，不原样回显服务器错误、请求头、响应正文或异常对象中可能包含的秘密。

## 5 请求一致性与现有工具

每个请求使用调用时捕获的凭证和代次，不通过修改共享 HTTP 客户端的默认认证头来完成更新。旧请求晚返回的 401 只能阻断旧代次，不能把已更新的新凭证标记为失败。不增加自动重试；用户下一次调用决定是否继续。

检索、详情、统计、认证检查及分类枚举均使用同一读取和错误处理路径。分类枚举现有独立请求绕过路径纳入此流程并启用 TLS 证书校验；这是此次认证恢复所必需的统一，不改枚举内容或检索条件。

认证检查必须先读取文件，不能因启动时缓存为空而提前返回。只输出认证状态及恢复指引，不返回用户身份。已有 `rmfyalk_set_token` 仅保留非持久兼容接口，不用于本流程、不在恢复提示中推荐；正常调用仍以本机文件为准，其成功/失败返回也不得泄露身份或凭证。兼容接口验证其输入时使用独立临时请求，不覆盖正常凭证源，也不能把文件中的凭证误当作兼容参数验证成功。本轮不会实际调用该接口传递任何真实凭证。

统计和导出循环遇到认证失败时应停止并明确报告，不能吞掉错误、持续翻页或将部分结果说成全部成功。没有新增导出授权；本轮真实验收不得调用批量导出或写入案件/法库目录。既有其他业务功能不扩大范围。

## 6 改动位置与依赖

原则上仅修改上游 `scripts/client.py`、`scripts/server.py`，增加本流程所需的聚焦测试及本机操作说明；如文件读取职责需要独立，最多增加一个小型认证读取模块。复用已有 `httpx`、`python-dotenv` 和 MCP，不新增依赖、框架或数据库。文件安全检查以实际打开的文件描述符为准，避免先检查路径再打开的替换竞态；不因此遍历其他文件。

不连带改变 `.env` 中既有 `EXPORT_DIR` 的启动读取语义。替换认证读取逻辑时应显式保留原导出目录配置用途，但导出授权与调用范围不变。

源码修改前留存非秘密的原版本和差异，保留上游许可与署名。修正与本流程直接相关的本机文件路径说明；不顺手改造其他连接、共享法规服务、Skill 行为或调度。现有包装器和连接注册原则上不改，首次加载改造通过正常重建现有连接完成，不批量终止其他任务进程。

工作区目前不是 Git 仓库，本设计仅保存为项目文件，不创建仓库或伪称已提交。跨机路径解耦和第二台 Mac 验收仍分别记录，不能把本轮源文件相对定位说成整个连接已完成迁移。

## 7 验收标准

先以虚构凭证、临时文件、模拟官网响应写失败测试，再实现。测试不得加载用户真实 `.env`、访问真实官网或启动真实导出。至少覆盖：

1. 同一个进程内从凭证 A 改成 B，下一次请求使用 B，无重启；同长度、同修改时间及原子替换也能发现。
2. 已有进程环境残留 A、文件为 B，正常请求使用 B；不能靠环境值掩盖文件缺失、空白或损坏。
3. 未设置、空值、非法格式、重复键、权限不合要求、非普通文件、符号链接、不可读及超大文件，均安全停止，不发送旧凭证。
4. 本地到期、HTTP 401、业务 401 均阻断同代后续请求；更新为 B 后可恢复；相同旧值重复保存仍不恢复。未知到期字段不会被称为认证有效。
5. 网络失败、TLS 失败、服务器非认证错误不误报过期、不改文件、不增加自动重试。
6. 并发旧 A 的迟到 401 不污染新 B；请求头不随另一次调用中途变更；失败不会关闭另一请求正在使用的连接。
7. 检索、详情、认证检查、枚举均能重新加载；枚举 TLS 校验为开启。统计/导出在认证失败时停止，不吞错、不冒称全部完成。
8. 把虚构秘密和身份字符串埋入认证测试响应及错误对象，全部相关工具结果、标准输出、错误输出和保存的测试报告均不得出现这些字符串。此项不授权改写公开案例正文。
9. 已有相关测试和工程回归通过；保留实际测试命令、结果与未覆盖项。独立审查代码与边界，不能仅以自检代替独立复核。

工程测试通过后，在用户本人更新有效凭证且新代码已加载的前提下，通过当前聊天已注册工具检查认证、查询一条真实案例、取得其详情。不得将临时独立会话成功代替当前工具成功；详情取自真实检索返回的 ID，不猜链接或案号。

没有新有效凭证时，可以完成并报告“工程恢复机制通过”，但“真实更新后的自动恢复”必须保留待验收。具体案例网页链接、原裁判全文、正式引用审阅和全国数据库完整性不因认证成功而自动完成。

## 8 设计自检与实施顺序

已区分到期提示与后台通知、文件更新与自动登录、本地解析与官网认证、工程测试与真实恢复、案例条目与原裁判全文。没有增加常驻服务、抓取授权或公开发布，没有要求用户传递秘密。

用户已确认，按实施计划完成先失败后通过的测试与代码修改、独立复核、首次连接重建及真实恢复验收。项目记忆只记录选择、实施状态和剩余缺口；实际凭证永不回写。
