# 个人本机模拟法庭首版设计

2026-09-28用户明确同意：先支持民商事一审，按争点整理、举证质证、法庭发问、双方辩论、复盘顺序运行；只用本次指定案卷，调用共享法库，保留每轮记录，不预测胜诉率，不提交法院。刑事、行政、执行另行验收。

## 目标与边界

这是律师准备庭审的内部演练，不是法院系统、不替代法定程序、不形成真实自认或裁判。沿用原Skill的事实状态、双模式审查、来源卡和律师审批规则；新增一个用户明确要求“模拟法庭”时进入的分支。中立咨询不自动路由到演练。

本机只读MCP继续仅提供公开法源，不新增私有案卷接口、联网发布或用户认证平台。本模块的文件边界检查可限制其自身的读取，但不能当作整个Codex宿主或多用户服务端案件权限验收。B44真实跨案身份授权仍单列未验。

## 数据和流程

- 一个演练目录对应一份会话记录；输入是用户本次指定材料整理成的案件包，固定case_id、程序、我方角色、材料清单、每项材料的相对文件路径与哈希。仅支持明确指定的UTF-8文本材料；其他格式先由已有专用技能转换，保留原件和转换说明，不假装原格式已验证。
- 不遍历或检索其他案件目录。读取路径必须位于指定案件根目录内，不允许绝对路径、父目录跳转或符号链接；材料不存在/哈希不符就停止，不能自动替换。
- 阶段固定为：准备 → 争点整理 → 举证质证 → 法庭发问 → 双方辩论 → 复盘。只能按顺序追加记录；每轮角色明确为主持/模拟原告/模拟被告/复盘员。主持发问不是事实认定，模拟回答不是新增证据。
- 每个回合保存case_id、阶段、角色、完整可见发言、使用的材料ID、来源卡、未决事项。仅保存对外可见的简短分析，不保存模型私有思维链。
- 演练协议允许同一模型模拟多角色，必须披露并非独立律师团队。给用户逐轮互动和一次完整合成演练两种执行方式；都不能跳过质证、反方回应和复盘。
- 每个承重法命题通过现有MCP检索/条文回读并记录真实来源卡；离线或来源禁止时明确未核，允许条件式讨论，不伪造核验。
- 复盘交付争点清单、双方强弱意见、证据缺口、法官可能追问、需修正文句、待核法与下一步；不输出确定胜负、精确胜诉概率、真实认罪/认责或已律师签发。

## 最小实现与复用

新增一个小型标准库模块和命令行入口负责路径/哈希、会话状态和追加记录校验；模型发言由Skill指导，不为本功能接入新模型API或收费账户。会话内容不进入公共法律库、公共索引、Obsidian或分发包。分发仅带合成样例和规则。

存储使用本机受限会话目录，追加操作使用文件锁及原子替换，拒绝覆盖既有会话；保留输入哈希以发现材料变化。文件边界保证限于工具自身，不宣称能隔离同一macOS账号下任意其他工具。

## 验收

1. 失败测试覆盖路径跳转/符号链接、材料哈希变化、不同case_id、阶段跳跃、未知角色/材料ID、重复初始化及写入失败；不得改公共DB。
2. 先跑旧Skill模拟法庭压力任务，实际记录缺口，再加最小分支和模板并用新会话前向测试。
3. 一份明确虚构的民事案件实际完成全部阶段，调用真实共享法库、保存所有回合和复盘；人工律师审核为null。
4. 独立复核代码和演练输出，区分工程通过、模型行为、权限限制与律师法律审核。源不足/事实不明不得为了通过测试补造。
