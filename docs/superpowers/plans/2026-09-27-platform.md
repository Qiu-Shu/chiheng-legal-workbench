# 持衡平台实施计划

> 执行方式：当前任务连续执行；用户已批准设计和缺失依赖下载。按子系统验收，记录实际结果。使用 executing-plans 的逐任务执行方式。

**目标：**先完成真实安装与可验证的采集基础，再建立法律库、检索、更新和私有入口。

**架构：**保留既有 P1 Skill；在项目独立虚拟环境安装依赖。公共资料先隔离保存，审核后才能成为法律依据。

**技术：**Python 3.12、Scrapling、SQLite FTS5、MCP、macOS launchd。

## 文件职责

- `requirements.txt`：直接依赖；`requirements.lock.txt`：实装版本。
- `scripts/smoke_scrapling.py`：静态、动态及实际网站读取验证。
- `docs/implementation-progress.md`：事实状态、失败、修复和下一步。
- `data/`：原始与隔离数据，禁止混入客户文件。
- `legal_store.py`、`tests/test_store.py`：版本化入库与中文检索；按独立子系统继续细化实现。
- `config/`：来源许可、调度和接口配置；仅通过已验证来源启用采集。

## 任务一：依赖与真实抓取

- [ ] 使用官方安装器安装 `D4Vinci/Scrapling/agent-skill/Scrapling-Skill`，固定实际仓库提交。
- [ ] 使用已存在的 Python 3.12 创建 `.venv`，执行 `.venv/bin/python -m pip install 'scrapling[all]==0.4.15' mcp pyyaml`。
- [ ] 执行 `.venv/bin/scrapling install` 下载运行浏览器。
- [ ] 执行 `.venv/bin/python -m pip check`；预期依赖无冲突。
- [ ] 执行 `.venv/bin/python scripts/smoke_scrapling.py`：本机测试页静态和动态提取中文必须一致；真实公开页面失败也记录，不计为成功。
- [ ] 锁定版本，输出安装记录和 SHA256。

## 任务二：法规库最小闭环

- [ ] 首先编写版本隔离、同文去重、中文短词检索、时间/地域过滤、审核状态过滤和回滚测试。
- [ ] 使用 SQLite 保存不可变正文、哈希、来源、时点和地域；以事务实现审核状态与索引同步。
- [ ] 原始版本状态保持 unknown；只有人工填写并核验生效日期、失效日期、适用地域后，才允许作为确定版本使用。
- [ ] 检索结果必须同时带来源、定位、时间、审核状态和正文片段。

## 后续子系统及依赖

1. 来源登记与采集：迁移 P1 注册表，加入全国官方机关、31省级地区覆盖缺口、吉林重点和工商执行；只对审定的路径开放后台采集。
2. 本地只读 MCP：先实测当前 SDK，再加入查询、详情、覆盖和健康工具；不向模型暴露审核签发操作。
3. 更新调度：先实现幂等、失败退避和最后良好版本，再安装用户已授权的 launchd。
4. Skill 更新：三个阶段使用同一结构与深度；只在文末区分验收状态；案件具体不确定性在原位标注。
5. Plugin：先验证账号和传输支持；localhost 地址不意味着云端 ChatGPT 可以直接访问，不自动开放公网或上传私有内容。
6. 商业数据：网页会员人工导入；API/MCP 待真实供应商授权，不购买、不索取密码或 Cookie。
7. 验收：工程测试与模型行为测试分别记录；50个场景存在不等于50项行为测试通过；律师签发由真实律师完成。

## 设计修订

- 所有当前许可只支持本机使用的商业数据必须留在本机；云端模型调用会产生数据传输，不能把“本地目录存储”描述为“没有外发”。
- Plugin 能力及本地连接必须实测后才能标记为已接入；不假设两个产品支持相同 manifest。
- 最初设计中的完整内容指相同标准，不承诺模型逐字相同或未知事实能够补全。

本文件是分阶段执行记录；后续子系统在前置接口确定后写详细测试和实现步骤，不以计划条目充当已完成功能。
