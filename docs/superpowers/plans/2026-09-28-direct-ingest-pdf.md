# 直接入库与引用时审阅实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 落实用户2026-09-28最新决定：通过机械完整性检查即可入库供检索，不逐份等待人工审批；真实引用时展示可审阅的来源字段。

**Architecture:** 保留原件、SQLite、只读共享MCP和现有审核历史。不把未人工复核资料伪装成已核验资料，不恢复已撤回的错误版本。新增有文字层PDF的双提取核验和逐页定位；无文字层或冲突资料保留原件、明确失败，不猜测补齐。

**Tech Stack:** 现有Python、SQLite、Scrapling；复用Codex随附pypdf/pdfplumber。

## 一、PDF提取（独立实施）

- [ ] 创建`official_pdf.py`及`tests/test_official_pdf.py`，先运行失败测试，再实现。
- [ ] 接口`extract_pdf(payload, expected_title) -> (text, manifest)`，项目环境调用随附Python，不重复安装依赖。10MB/100页/60秒有界。逐页保存两工具原始文字及页码、正文起止偏移、正文哈希；两个提取器去空白后须一致（仅允许几何位置确认的页脚页码差异）。标题一致；拒绝加密、扫描件、图片/表格等未经处理结构和不一致结果。
- [ ] 真实11页湿地原件必须通过；每页`text[start:end]`与该页正文一致，末页施行文字保留。测试涵盖错误标题、损坏/非PDF、空白、页码污染、双工具差异和偏移。
- [ ] 不写正式库、不修改共享查询代码。由主实施者集成唯一PDF附件支持。

## 二、先检索、引用时复核

- [ ] `tests/test_citation_policy.py`先验证未人工复核的新入库资料默认可查、显式审核过滤仍生效、撤回资料不进入检索、未知时间不得伪装有效。
- [ ] 修改`legal_store.py`和`legal_mcp.py`：默认包含未人工复核资料，搜索排除最新审核动作为撤回的版本；保留原有发布机制而不调用批准接口。
- [ ] 统一返回`citation`：标题、来源详情链接、原件链接、机关、地域、版本ID、原文哈希、采集时间、条号/页码/字符定位、审核状态、时间字段及字段缺失清单。未知字段为null并明确未核验。无页码的历史资料不可编造页码。
- [ ] PDF定位及元数据以独立版本来源记录保存，不重写法律正文；查询返回与当前片段相交的页码。
- [ ] 更新共享契约与当前安装Skill引用规则：每一实际法律命题就地附来源卡，案例适用和律师签发仍由用户决定。

## 验收边界

测试成功只证明工程行为，不等于全国完整覆盖、逐份法律审核或50个模型行为场景完成。用户明确把人工审阅移到实际引用时，因此无需每份法规再次确认。
