# 萌律共享公开法律库：第一性原理与接口约定

用途以用户2026-09-27最新说明为准：个人非商业学习。共享的是公开法源基础，不把持衡的审查方法强加给其他Skill。

## 为什么不是每个Skill各建一套库

同一条法律一旦出现多个副本，不同Skill容易引用不同版本。将“法律资料的版本与来源管理”集中，将“婚姻、劳动、合同、执行、诉讼攻防等分析方法”分开。当前复用已存在的JSON语料、legal-tools在线接口和SQLite，不另造通用爬虫、MCP或向量引擎。

```text
各法律Skill（不同分析方法）
       │
       ├── 共享离线镜像：找法名、条号、候选片段
       ├── SQLite审核集合：版本、来源、审核状态、时间/地域
       └── 官方联网工具：关键条文、版本与上下文核对
                    │
           Obsidian索引/核验卡片/缺口记录
```

实现暂保留在原项目目录，连接名 `chiheng-legal` 为兼容保留；服务已独立于诉讼审查Skill。不是再次复制2190个版本。未来迁移存储目录只需改 `config/shared-library.json`，不改变消费者接口。

## 四类数据隔离

| 类别 | 当前处理 | 不允许混同 |
| --- | --- | --- |
| 公开法源 | 旧JSON只读镜像、SQLite原文版本、官方链接/快照 | 镜像有效标签≠核验结论 |
| 工商执行/商业资料 | 只测公开入口；会员人工查询/官方导出 | 首页可达≠主体查询成功，网页会员≠API授权 |
| 私有案件 | 不进入共享库，不自动读取 | 个人学习用途≠案卷外发授权 |
| Obsidian记忆 | 项目决策/目录/动态看板/核验卡片 | 记忆摘要≠法律原文，全文不会注入全局记忆 |

## 最小可用引用

2026-09-28用户决定：先入库供检索，真实引用时审阅；不再逐份等待人工审批。默认`search_law(include_quarantine=true)`包含未人工复核且未撤回的资料，显式false仍仅人工审核版。quarantine保留为技术状态，不自动发布。已撤回错误版本不进入检索；按版本历史回读会明确withdrawn。as_of只筛已确认的日期，来源观察日期不用于冒充已确认时间效力。

三个SQLite检索/取文接口均返回`citation`：名称、机关、文号、详情/原件链接、版本、地域、条号、PDF页码或字符位置、哈希、采集时间、已确认时间字段、来源观察日期和缺失字段列表。未知字段为null，引用时明确未知。每个实际法律命题就地展示来源卡与原文；本地保存或链接返回不等于本次联网核验。原始PDF双提取报告单独留证，数据库只保存小型页码索引。私人案件签发和事实处分授权不受此入库决定影响。

`compared_pdf_originals`逐份列出已严格提取并与所选全文去空白比对成功的PDF链接、原件/文字/归一文字哈希和总页数；仅为机械比较，不代表排版或法律适用一致。不能将其他格式总页数套作当前文字的具体页码。`uncompared_alternative_urls`继续明确未比对原件。地方入库正文、索引、来源及回读校验已采用同一事务，任一失败不留下不完整新记录；不会覆盖既有来源事实。

引用应含文件名称、来源URL、版本ID、条款/款项或原件页、原文片段、抓取/核验时间、哈希、来源层级和核验范围。生效日、废止日、公布日和获取日分别记录；未知保持未知。

`search_public_corpus`只做字面检索候选，支持二字中文但不是语义检索。其上游日期/状态不作已核验筛选。`search_law`支持审核集合的as_of和region；历史适用仍须复核过渡规则和地域。

`get_law_article`按SQLite版本ID和精确中文条号返回固定原文中的字符位置、条文哈希和分页片段。复用既有不可变全文，2026-09-28新增独立provenance表存来源字段与PDF页码，不复制全文。当前民法典固定DOCX样本的1260条机械验收见`verification/civil-code-article-acceptance.json`；不是所有格式的解析保证，也不把目录/附件/引述歧义猜成正文。旧镜像的1062单元仍原样保留。

## 交通裁量表格引用

交通集合继续使用同一组只读接口，不为不同律师 Skill 复制数据库。先用 `search_law` 找到具体 `version_id`，再用 `get_law_fragment` 读取正文及其 `citation`。表格正文是原格内容与生成定位标签的检索投影，不是重新制定的法律文本；原件摘要 `original_sha256` 和投影摘要 `text_sha256` 分别保存。

检索是全文匹配：附件名称也可能出现在通知目录或其他表的备注中。关键词命中不等于已经选中该附件；还须核对资料标题、`attachment_id`、版本和来源后再取文。

| 来源卡字段 | 用途 |
| --- | --- |
| `collection_id`、`attachment_id`、`parent_notice` | 识别所属通知和附件，不能单凭文件内编号归类 |
| `verified_sources` | 各已留证来源的官方原件链接、网页附件名及原件摘要；观察日不是本次重新联网时间 |
| `internal_number`、`internal_title` | 保留文件内原始标号与标题，即使与网页不一致也不改写 |
| `differences` | 显示两来源差异、双方原件直达链接及摘要，不自动裁定哪份正确或有效 |
| `locations` | 与当前片段相交的工作表、行、单元格及字符区间；`merge_anchor` 标明继承内容的真实合并锚点 |
| `source_dates_scope`、`source_dates_url` | 说明日期来自父通知；不冒充附件创建时间、独立发布日期或已确认生效时间 |

表格的 `get_law_article` 明确返回未找到，并提示改用片段接口，避免把表内引用的“第一条”误认成该表自己的条文。取得某行的字符范围后，应读全该范围；每次最多10000字符，超出时继续分片。引用需同时核对代码、违法行为、法律根据、违法程度、判断基准、处罚基准，以及相关表尾备注，不能只摘出罚款数额。普通空格不会自动向下填充；空工作表也保留在结构清单中。

`raw_text` 是保存的单元格原值文字，`display_text` 保留已经核验的数字显示格式。例如原值7.5与事项编号7.50不能混成两个处罚项目，也不能把数值编号当唯一身份。表格位置以原件摘要、工作表和行列确定。不支持的工作簿仅归档原件与失败说明，不进入正文检索；没有命中不能推断没有相关规定。

其他 Skill 可以复用这样的请求：“调用共享法库检索本案主题；如命中裁量表，展示完整对应行、合并锚点、官方来源链接和已知版本差异；不要自动计算罚款，未知效力日期明确说明。”引用时仍由使用者审阅。该功能的真实入库与迁移范围见 [交通资料交付记录](traffic-cell-library-delivery-2026-10-03.md)，不能由接口可用推断八表或全国资料全部完成。

## 不把检索测试冒充法律审核

- `verification/shared-library-smoke.json`是接口验收。
- `verification/official-fragment-probes.json`是4组实际官方关键词片段；不保证全文或完整条文。
- `data/review-records.jsonl`区分 automated/human、fragment/entire_law/entire_case。match是文本比对，不自动发布或判定案件适用。
- 案例记录分别存 `case_reference_status` 与 `judgment_validity`；指导性/参考/普通裁判/典型案例分层。
- 代码中的human是申报类型，不是身份认证或律师电子签名。当前人工审核发布量仍为0。

## 覆盖如何衡量

先建立“地域×机关×文件类型×领域×时间”目录，再计算有目录/有全文/可定位/核验过/按期刷新数量，分母未知时不报告虚假的百分比。地方库已归档的上游仅作线索；国家上游的目录数量也不代表其下载成功数量。

每个具体学习问题最终交付正反依据、缺失资料和检索范围。三个验收版本仍使用相同内容标准；仅文末版本提示不同，具体不确定性在相关结论处标注。
