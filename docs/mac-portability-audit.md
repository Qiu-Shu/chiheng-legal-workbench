# Apple Silicon Mac 可移植性要求与现状

日期：2026-09-28。用户新增硬性要求：今后可以在自己的其他 M 芯片 Mac 上安装和使用同一法律库。用户随后确认实施。以下缺口是改造前检查；数据迁移、路径解耦和原生安装器已实现，实际检索模式安装通过；第二台 Mac 尚未实测。

## 已发现的迁移缺口

- 当前 ZIP 是源码/Skill 交付包，构建脚本明确排除了数据库、法律原文和运行环境，不能用它证明完整迁移。
- SQLite 主库使用项目相对路径，但旧法律镜像的 `config/shared-library.json` 指向另一项目的本机绝对路径。
- `legacy_doc.py` 的 LibreOffice 路径、基础法导入器的上游项目路径、Obsidian 看板默认路径绑定本机用户名。
- 两个现有 LaunchAgents 的解释器、工作目录与日志路径绑定本机；目标电脑需要重新生成，不应原样复制。
- 现有 requirements.txt / requirements.lock.txt 尚未声明已使用的 pypdf、pdfplumber；需要补齐并在干净环境验证，不能把本机可运行等同于可重装。
- SQLite 启用了 WAL。运行中单独复制主数据库不构成完整备份；需要一致性快照，并协调原件和采集状态的保存时点。

## 已确认方案

采用“个人数据迁移包 + Mac 本地安装器”，保留既有 SQLite 和共享检索接口，不另造数据库，不要求 Docker。

1. 数据包包含数据库一致性快照、原件、来源与审核/撤回记录、所需公开镜像、采集检查点、版本清单和文件哈希；独立于可公开分享的源码包。镜像保留来源和许可记录，不把个人迁移当作公开再分发授权。
2. 运行依赖在新电脑按受测版本重建，不复制旧 .venv 或旧电脑缓存；检查 Apple Silicon、Python、SQLite FTS5/trigram、PDF/Word 处理依赖和可选浏览器依赖。缺依赖明确报错，不自动降级成有缺字的抽取。
3. 机器路径集中配置；数据库与原件使用可迁移相对位置。历史来源记录中的旧路径作为历史证据保留，不擅自改写成新来源事实。
4. 安装器按新用户名、目录及用户身份生成本地服务和连接配置；仅监听本机。先验证检索，再启用自动更新；保留并检查旧检查点，避免一次迁移触发不受控补抓。
5. Obsidian 只让用户选择新 vault；生成托管索引，不复制整个私有知识库，不覆盖非托管笔记。不迁移会员会话、Cookie、密钥；需要时在新机重新授权。
6. 安装可重复执行，遇到已有数据库不覆盖；损坏包、漏文件、路径越界及版本不兼容应拒绝导入，失败保留旧库并给恢复说明。

备选：手动复制再逐项配置，工作少但容易漏文件；容器化可隔离依赖，但增加 Mac 后台与维护负担。本项目优先原生安装方案。

## 验收标准

- 在不同目录、含空格/中文路径下，从迁移包恢复；逐项核对文件清单/哈希、数据库完整性、版本/来源/审核/撤回记录及原文链接。
- 干净环境重建依赖；已有七个共享工具回读一致，不依赖源电脑的绝对路径或缓存。
- 验证重复安装、残缺包、目标已有数据、端口冲突及启动失败；不破坏当前运行服务。
- 区分“本机换目录演练”“新用户/干净环境测试”“第二台 M 芯片 Mac 实测”。未有第二台设备的实际结果前，不标称跨机验收完成。
- 多机同时使用先按独立副本处理。本轮不包含实时双向同步、冲突合并或云端服务；这些需要另行设计。

当前证据见 verification/mac-transfer-acceptance.json 和 verification/portable-runtime-acceptance.json：431文件个人数据包已换目录恢复，39全文/来源/审计及7共享工具通过；旧镜像2190版本仍未核验。机器路径已拆分，未复制机器配置到恢复目录。独立环境2份PDF共29页重新抽取正文哈希一致。完整浏览器依赖因下载问题未通过清洁重装；原有服务未重启，未改法律内容。

此前吉林三份官方正文页的预检记录及成功取得的两份页面原件仍保留，另一次下载失败，均未因此计为新入库。

安装器实际在另一个中文含空格目录重建独立环境：39全文/默认检索、7工具、镜像回读通过；重复安装拒绝且数据库与安装状态未变。生成的服务路径指向新目录，未注册第二套服务。280工程测试通过，独立复核缺口修复后关闭。检索模式未安装Scrapling/httpx或外部国家库客户端，因此明确ready_update=false，不伪装为自动更新已迁移。详细步骤见mac-migration-guide.md，实测记录见verification/installed-runtime-acceptance.json。
